# 外部泛化誤報診斷

## 範圍與結論

本分析使用 `generalization-20261025-1322` 的凍結 checkpoint、原門檻，以及已完成評估的
101,289 筆資料。經使用者同意，外部標籤現在用於開發診斷；後續改版模型不能再把這份
資料稱為未參與開發的盲測資料。

**主要問題是規則在新分布上失效，尤其會把一般英文中的 AND 與缺少 SQL token 的組合
當成 SQLi。這不是只由 Accuracy 或類別比例造成的視覺落差。**

本次沒有重訓、增量更新、刪除規則、改門檻或自動改標籤。原始外部報告仍是原模型
當時的歷史結果；這份文件是事後診斷，不是新模型成效報告。

機器可讀結果：
[error-analysis.json](../data/experiments/external-error-analysis-20261025-verified/error-analysis.json)。

## 1. 問題有多嚴重

保留資料包含 benign 48,879 筆、malicious 52,410 筆：

| 模型 | TP | FP | TN | FN | Accuracy | Recall | FPR |
|---|---:|---:|---:|---:|---:|---:|---:|
| Pure ARM | 51,839 | 38,252 | 10,627 | 571 | 61.67% | 98.91% | 78.26% |
| Hybrid | 51,878 | 38,942 | 9,937 | 532 | 61.03% | 98.98% | 79.67% |

也就是每 100 筆正常輸入，大約有 78 至 80 筆被攔成攻擊。高 Recall 不能抵銷這個問題。
Pure 的 AP 為 60.22%，Hybrid 為 57.10%，而正類比例為 51.74%；排序能力也有限，
所以不能假設只改一個門檻就能同時保留高 Recall 並大幅消除誤報。

## 2. 一條規則已足以解釋大量 Pure 誤報

下列 ID 對應凍結模型的原始規則索引，不是依本次排序重新編號：

| ID | 規則條件 | 訓練 confidence | 舊 Training 命中 benign / malicious | 外部命中 benign / malicious | 外部命中資料中的 malicious 比例 |
|---|---|---:|---:|---:|---:|
| 4 | AND 且沒有 WHERE、沒有分號 | 99.19% | 21 / 2,558 | 33,139 / 13,409 | 28.81% |
| 7 | 有比較特徵、沒有分號、沒有等號 token | 99.83% | 5 / 2,993 | 16,443 / 14,237 | 46.40% |

規則 7 的實作名稱為 `NOT no comparison, NOT token:semicolon, NOT token:equals`，
「比較特徵」依現有特徵擷取器定義，不是 SQL 語法解析結果。

Pure 使用「命中規則中的最高 confidence」作為分數，門檻固定為
`0.9219152854511972`。因此規則 4 的 confidence 足以讓任何命中輸入判為 SQLi。
它涵蓋：

- 全部外部 benign 的 **67.80%**：33,139 / 48,879。
- Pure 外部 FP 的 **86.63%**：33,139 / 38,252。

這證實該規則是這些輸入觸發 Pure 告警的充分條件，但不表示刪掉它就能消除
33,139 筆誤報：同一筆資料可能還命中其他超過門檻的規則，必須另做消融實驗。
規則 4 與 7 的命中數也不能直接相加。

### 為什麼正常英文會命中

Tokenizer 對 `AND` 使用單字邊界的大小寫不敏感比對；它不是把 `candy` 裡的
子字串誤認為 AND，而是無法區分英文連接詞 `and` 與 SQL 邏輯運算子。
沒有 WHERE 或分號也很常見於正常英文。

例如自行撰寫的正常句子：

> The acting and dialogue were excellent.

會命中規則 4。已新增測試直接驗證此行為，沒有改動正式 tokenizer。
這說明「負向條件 + 常見單字」缺少足夠 SQL 上下文，而不是這句話真的含有注入。

固定種子抽出的 FP 樣本可見影評、一般英文、縮寫撇號與 HTML 換行標記。
這是人工檢視線索，不代表已完成全資料標籤稽核，也不能推定所有 FP 都具有相同來源。

## 3. Hybrid 沒有修好這個分布轉移

Hybrid 同時讀取六個數值特徵與固定規則特徵；本次外部測試中分類器是凍結的，
沒有根據新標籤更新。

- 規則 4 命中的 33,139 筆外部 benign，Hybrid 也全部判為攻擊。
- 這占 Hybrid FP 的 **85.10%**，但仍是重疊覆蓋，不是因果特徵重要性。
- 單一 AND 規則（ID 13）涵蓋 36,423 筆 Hybrid FP，但其 confidence 僅 78.45%；
  不能說這條規則單獨決定了 Hybrid 結果。
- Hybrid 的 `0.9999999999999896` 是分類器輸出門檻，不能拿單條規則的 confidence
  跟它比較後，就推論規則對分類器有沒有作用。

要確認 Hybrid 是多大程度依賴負向規則、長度或其他特徵，需要在開發資料上重新訓練
受控模型並比較，不能從共同命中直接當成已證實的因果歸因。

## 4. 正常資料的樣貌確實變了

同 checkpoint 診斷中的數值如下；長度以現有 Java 特徵擷取器計算：

| 群體 | 長度平均 | 長度中位數 | discontinuousDensity 平均 |
|---|---:|---:|---:|
| 舊 Training benign | 46.10 | 39 | 0.1186 |
| 外部 benign | 474.63 | 466 | 0.1766 |
| 舊 Training malicious | 111.04 | 78 | 0.3393 |
| 外部 malicious | 495.37 | 477 | 0.1170 |

外部 benign 的平均長度約為舊 Training 的 10.30 倍，且某些特徵與標籤的關係改變。
長文更容易出現 AND、撇號、括號等常見表面特徵，但長度本身不是 SQLi 證據。

同時，至少命中一條負向規則的 benign：

- 舊 Training：132 / 16,395，約 **0.81%**。
- 外部資料：38,200 / 48,879，約 **78.15%**。

這是規則適用分布改變的直接描述，不是「每個負向規則都不應存在」的證明。
部分 malicious 抽樣也有填充文字或混淆片段，但不能僅憑抽樣確認上游生成方法、
真實可執行性或標籤正確性。

## 5. 可以與不可以下的結論

**有證據支持：**

1. 目前兩個凍結模型對這份外部資料有嚴重誤報，不適合當成可直接全面攔截的成果。
2. 舊資料上的高 confidence 不等於外部攻擊機率；規則 4 的外部命中正類比例只有 28.81%。
3. 一般英文與負向規則之間存在可重現的誤報機制，Pure 尤其明確。
4. 外部 benign 與舊 Training benign 有明顯特徵分布差異。

**目前不能證明：**

- 這次落差一定是 Test 資料洩漏、模型容量過大，或傳統意義的 underfitting。
- 只要加入更多同類資料、做增量更新、刪規則或提高門檻就一定改善。
- Kaggle 標籤全部正確或全部錯誤；樣本缺少 SQL 執行上下文時尤其需要人工稽核。
- 規則與分類器都使用 Training 就自動等於 Test 洩漏。先前 disjoint 訓練實驗也沒有
  穩定勝過原策略，不能把拆開訓練當成已證實的解方。

「學到只對舊來源有效的捷徑」比「已證實 overfitting」更精確。要區分來源偏差、
標籤問題與模型設計，還需要受控開發實驗。

## 6. 建議改善順序

1. **先做標籤與輸入情境稽核。** 明確定義輸入是使用者欄位、完整 SQL，還是一般文字；
   分來源檢視 benign 與 malicious，將爭議標籤獨立記錄，不為改善分數直接改標。
2. **建立新的開發資料與新的最終 holdout。** 納入長英文、中文、HTML、撇號、AND/OR、
   合法 SQL 等實際正常輸入，並以來源／模板分組。這份已診斷資料可以作開發參考，
   但下一版成果需要另一份未使用資料。
3. **受控比較規則限制。** 比較原版、禁用負向規則、要求足夠正向 SQL 上下文、
   避免單一常見 token 規則等方案。每個方案都報 FPR 與 Recall，不能只挑 Accuracy。
   不要把單一外部 FP 範例寫成特例白名單。
4. **對 Hybrid 做特徵消融。** 比較數值特徵、正向規則、完整規則及簡單基準；
   固定資料分割與種子，分來源呈現結果，判斷規則特徵是否仍帶來穩定收益。
5. **最後才在 Validation 選門檻。** 依產品能容忍的 FPR 與最低 Recall 定義目標，
   檢查可達成性及信賴區間；若無可行門檻就回到資料與特徵，不能以外部測試集調整。
6. **另行驗證增量學習。** 使用先預測、後揭露標籤更新的時間／串流評估，
   比較不更新與更新模型，避免對已更新的同筆資料重測後宣稱泛化提升。

以上是下一輪開發順序，不是本次已完成的模型改善。

## 7. 驗證與重現

診斷程式會：

- 核對外部 export、checkpoint、development report 與舊 Train/Validation 的 SHA256。
- 以凍結門檻重新取得分數，強制確認 Pure/Hybrid 的 TP、FP、TN、FN 與原報告完全一致。
- 在完成前再核對輸入 hash；任何差異會將診斷標為失敗，不產生成功形狀的替代結果。
- 每個 outcome 固定種子抽至多 12 筆供人工檢視；這是按列抽樣，不是各模板等權抽樣。
- 保存各規則重疊命中數、特徵分布與輸入 hash，不覆寫原外部報告。

從 backend 目錄執行，輸出必須是尚不存在的新目錄：

```sh
mvn -q -Dtest=ExternalErrorAnalysisTest,GeneralizationPipelineTest test
mvn -q exec:java@external-errors \
  -Dexec.args="data/experiments/generalization-20261025-1322 data/experiments/external-error-analysis-NEW"
```

這是已揭露標籤後的固定模型重算與誤差診斷，不是重新執行首次外部測試協定。
